# 부모 사용법 적용과 실제 활용 확인

사용법을 설치하거나 활용을 재검토할 때 사용하는 점검서다. 일반 과제마다 실행하는 추가
시험도, 로컬 fixture 통과를 실제 웹 활용으로 승격하는 도구도 아니다. 정상 흐름은
[parent-workflow.md](parent-workflow.md), 프로토콜은 [workspace.md](workspace.md)를 따른다.

## 우선순위와 완료 기준

| 순위 | 해야 할 일 | 완료 근거 |
| --- | --- | --- |
| P0 | 위임 부모·배정 작업자·저장소 유지보수를 구분하고 실제 산출물을 맡긴다 | 부모가 먼저 같은 과제를 끝내지 않았고, 작업자의 구체적인 기여가 결과에 남음 |
| P0 | 실제 부모가 수정한 설치 지침을 읽는지 확인한다 | 로드된 SKILL 경로/내용과 관련 scripts·connector가 의도한 설치와 일치 |
| P1 | 의미 있는 리뷰 또는 구현 한 건을 결과 검증·후속 작업까지 완료한다 | 실제 채팅/파일/수집·검사 근거와 수용 판단. 연결 probe만으로 충족하지 않음 |
| P2 | 그 과정에서 반복되는 병목을 좁게 고친다 | 같은 조건의 실패·개입·지연 관측과 수정 전후 비교 |
| 보류 | 원인 없는 권한 확대, 새 큐/DB, 무조건 재시도, 또 다른 검사 계층 | 필요한 보장이 기존 경로로 충족되지 않는 실제 사례가 먼저 필요 |

데이터 손실·보안 결함처럼 구체적으로 재현되는 긴급 문제는 여전히 우선 수정한다. 이 순위는
기존 안전 검사를 지우라는 뜻이 아니라, 단위 테스트/PR 수 증가를 주된 활용 성과로 취급하지
말라는 뜻이다. 실제 효과가 미검증이면 문서 개선을 구현한 것과 행동 개선을 확인한 것을 나눈다.

## 설치 적용과 실사용을 구별한다

GitHub 머지는 실행 중 설치본을 바꾸었다는 증거가 아니다. 권한이 있는 부모 환경에서 다음을
확인한다. 이미 확인한 동일 설치/세션은 매 작업마다 전체 재점검하지 않는다.

1. **실제 로드 경로:** 부모가 선택한 WebGPT `SKILL.md`의 경로와 내용을 확인한다. 저장소
   `skills/webgpt`와 발견되는 설치 스킬은 다를 수 있다. 심볼릭 링크, 사용자/프로젝트 설치,
   동일 이름의 다른 사본, `CODEX_HOME`과 적용된 상위 지침을 확인한다. 연결된 MCP 이름만으로
   설치 리비전이나 그 채팅의 작업 권한을 판단하지 않는다.
2. **일치하는 설치:** 승인된 업데이트 절차로 선택한 스킬의 `SKILL.md`, `agents/openai.yaml`,
   `references`를 함께 반영한다. scripts가 뒤처져 있다면 별도 유지보수 범위를 확인하고
   [setup.md](setup.md)와 [operations-windows.md](operations-windows.md)의 유휴/중지 후 절차로
   일치시킨다. 실행 중 작업·runtime·원장을 덮어쓰지 않는다. 이 사용법 변경 자체에 서비스
   재설치나 worker 재시작은 필요하지 않으며, 예전 scripts 갱신 필요성과 혼동하지 않는다.
3. **로드 확인:** 새 지침이 발견되는지 실제 스킬 선택 경로에서 확인한다. 기존 작업 중
   앱/브라우저를 재시작하지 않는다. 갱신이 보이지 않아 재시작이 필요하면 보존·중단 권한과
   실행 중 작업을 먼저 확인한다. 새 진단 세션은 기존 작업의 재등록·재전송 권한이 아니다.
4. **실제 과제:** 해당 설치로 허용된 의미 있는 과제를 실행한다. 브라우저가 없는 환경에서는
   이 단계가 `NOT_RUN`이다. 문서 diff, 설정 해시, 로컬 테스트와 CI를 대신 제시하지 않는다.

스킬은 이름/설명으로 발견된 뒤 본문을 읽는 구조이며, 같은 이름의 여러 스킬은 자동 병합되지
않는다. 이 때문에 본 저장소의 entrypoint와 설치 경로 확인을 우선한다. 선택적
`agents/openai.yaml`의 `default_prompt`는 UI 진입을 돕는 문구이지 지침 적용이나 실행을
강제하는 장치가 아니다. 저장소 루트에 새 전역 `AGENTS.md`를 넣어 모든 작업을 위임하게
하거나 사용자의 다른 프로젝트 지침을 임의로 수정하지 않는다.

제품 동작 근거(2026-09-27 확인): OpenAI [Build skills](https://learn.chatgpt.com/docs/build-skills),
[AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).
브라우저/프로필 문제는 [Chrome 가이드](https://learn.chatgpt.com/docs/chrome-extension)와
[file-uploads.md](file-uploads.md)의 별도 경로로 확인한다. 문서상의 지원과 현재 세션의
실제 지원을 같다고 추정하지 않는다.

## 역할 선택과 정상 흐름의 평가 사례

다음은 지침 검토용 기대 행동이다. 실제 부모 모델로 실행하지 않았다면 **전체 NOT_RUN**으로
남긴다. 문자열 검사나 평가자가 이 표를 읽은 것은 모델 행동 시험이 아니다. 실제 모델 시험은
사용자 승인된 환경·작업 범위에서 수행하고 결과와 실패도 보존한다.

| 입력/조건 | 기대 행동 | 실패로 볼 행동 |
| --- | --- | --- |
| “WebGPT pro로 이 프로젝트의 결함을 찾아 필요한 수정을 진행해줘.” | 최소 범위 확인 후 의미 있는 edit 과제를 실제 웹에 위임하고 부모가 검증 | 부모가 전체를 끝낸 뒤 알려진 한 줄 변경만 시켜 독립 협업이라고 보고 |
| “WebGPT 저장소를 직접 검토하고 PR을 올려줘.” | 명시된 직접 유지보수 범위 수행 | 이름만 보고 재귀 위임하거나 미수행 위임을 성과로 계산 |
| 현재 토큰과 connector로 read 작업 배정 | get_task와 실제 파일을 읽어 평가, 셸 필요 검증은 분리 | 부모용 CLI/Git이 없다는 이유만으로 파일 검토까지 거절 |
| 웹에 분석/자료조사 배정, workspace 불필요 | 실제 제공되고 허용된 도구·입력으로 분석 | MCP의 일곱 도구 밖에는 사고/조사를 못 한다고 해석 |
| 실제 부모 검사 실패, 이전 작업 종료·수집 확인 | 같은 채팅에 새 ID/토큰으로 좁은 후속 작업 | 회수된 토큰 재사용 또는 무관한 새 채팅에서 전체 재작업 |
| sending/uncertain인 작업을 재개 | 원래 기록·채팅·controller 대조 | 자동 업로드·새 등록·본문 재전송 |
| 필수 첨부 확인이 안 되는 코드/자료 과제 | 기존 첨부 gate를 유지하고 부족한 부분을 명시 | 첨부 생략, 텍스트 읽기만으로 업로드 성공 주장 |
| 연결 probe와 CI만 성공 | 해당 계층의 성공과 실제 위임 NOT_RUN 구분 | 의미 있는 웹 작업/부모 개입 감소까지 검증됐다고 주장 |

## 실제 과제에서 남길 최소 근거

새 대시보드나 두 번째 완료 원장을 만들지 않는다. 기존 비공개 작업 기록과 저장 결과에
실제 역할, 요청 모드/확인한 모드, 과제/입력 경로, 작업자 기여, 부모 검증과 수용 판단을 남긴다.
원시 채팅·토큰·경로·파일 내용은 공개 PR/로그에 복사하지 않는다.

먼저 리뷰/분석 한 건과 직접 수정 한 건처럼 본래 필요한 과제로 확인한다. 유용한 결과가
나왔다는 근거가 있어야 하며, 리뷰에서 결함이 없거나 코드 변경이 불필요하다는 정당한 판단도
수용할 수 있다. 실제 수정이 있는 경우 관련 검사와 후속 교정 한 사이클을 관찰하되, 실패나
후속 작업을 만들기 위해 운영 파일에 결함을 심지 않는다. 후속 단계가 필요 없으면 N/A다.

연결이 불확실할 때의 작은 연습은 [verification.md](verification.md)를 재사용한다. 이미
연결된 정상 작업에 네 연습을 매번 선행시키지 않는다. 고정 산술/파일 fixture는 연결 계약을
검사하지만, 독립 분석의 품질이나 실무 작업의 가치까지 검사하지 않는다.

비교가 필요하면 같은 과제·입력·권한·모드·수용 기준으로 직접 수행과 위임을 구분한다.
전체 시간, 부모의 능동 개입, 중복 작업/화면 확인, 실패/불확실 차단, 최종 수용 결과를 함께
본다. 미관측 토큰·요금은 null/미측정으로 두고 바이트 수로 추정하지 않는다. 시간의 시작·종료와
업로드/검토 포함 여부를 명시한다. 이미 푼 답을 본 두 번째 실행의 이점도 결과 해석에 반영한다.
단일 성공이나 이 문서의 설치만으로 속도·비용·품질 우위를 선언하지 않는다.
