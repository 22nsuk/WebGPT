# WebGPT 실사용 가이드

WebGPT는 로그인된 웹 ChatGPT에 요청된 결과의 완성을 맡기는 방식입니다. Git 프로젝트뿐
아니라 일반 로컬 폴더·텍스트·첨부 데이터·문서/미디어·연결된 앱에도 적용됩니다. 사용자는 목표와
입력·필요한 제한을 주고, 워커는 가능한 생성/수정·검증·교정·전달까지 수행합니다. Codex는 범위와
권한을 정하고 결과를 검토하며 실제로 필요한 보조만 합니다. 설치나 연결이 필요하면
[setup.md](setup.md), 실제 등록·결과 수집 절차는 [workspace.md](workspace.md)를 따릅니다.

프로젝트를 연결한다는 설명은 [참고 프로젝트](https://github.com/faithforone/WebGPT)의
사용 방식과 같습니다. 다만 이 포크는 프로젝트 범위의 텍스트 파일 도구를 유지합니다.
참고 커밋 `b8206c57866cf574fdb65aa2aadc146a4ad2e469`의 터미널 실행 권한이나
`webgpt open` 명령을 가져오지 않습니다. 로컬 폴더에 Git은 필요하지 않습니다. MCP의 파일
제한은 웹 워커의 별도 분석·생성·앱 도구의 한계와 다릅니다. [일반 작업 완료 지침](task-completion.md)에
따라 실제 입력·도구·전달 경로로 판단하고, 부모 환경에서만 가능한 단계만 Codex에 맡깁니다.
직접 PR 게시·CI·리뷰 후속 작업을 맡겼다면 웹 ChatGPT의 별도 GitHub 앱에서 현재 제공되는
도구를 탐색해 사용합니다. MCP의 셸 부재를 GitHub 쓰기 불가로 해석하지 않습니다.
기능 확인과 완료 기준은 [GitHub 작업 안내](github-workflow.md)를 따릅니다.

## 부모가 먼저 해야 할 일

사용자는 목표와 필요한 제약을 주면 됩니다. 부모가 [parent-workflow.md](parent-workflow.md)에 따라
의미 있는 분석·검토·구현 결과를 맡기고, 실제 기여를 받아 검증·수집합니다. 같은 문제를 부모가
이미 다 푼 뒤 연결 시험만 수행하는 것은 독립 위임을 대체하지 않습니다. 현재 토큰을 받은
작업자와 WebGPT 저장소 자체를 직접 유지보수하는 요청은 부모 위임과 구분합니다.

새 사용법을 적용할 때는 [설치·실사용 확인](parent-acceptance.md)을 따릅니다. 머지된 저장소와
부모가 실제로 로드한 스킬은 다를 수 있습니다. 새 지침 적용만으로 실제 활용이 검증되지는 않습니다.

## 작업을 맡기는 예시

아래 경로와 목표를 실제 작업에 맞게 바꿉니다. `xh`/`xhigh`는 Extra High(기본값),
`p`/`pro`는 Pro를 요청합니다. 요청한 모드는 웹 UI에서 확인하며 임의로 바꾸지 않습니다.

**Git 없는 로컬 폴더 — 직접 수정**

```text
WebGPT pro로 C:\work\notes의 안내문을 읽고 용어와 문서 간 링크를 일관되게 정리해줘.
이 폴더에는 Git이 없어. edit 권한으로 실제 파일을 수정하고 내용·링크·변경 범위를 확인해줘.
원래 의미와 무관한 파일은 보존해줘. Git 초기화나 업로드는 필요 없어.
웹 워커가 가능한 수정·검증을 마치고 변경 내용과 남은 한계를 보고해줘.
```

**첨부 데이터 — 결과 파일까지 완성**

```text
WebGPT xh로 첨부한 CSV의 누락·중복을 확인하고 월별 집계가 포함된 XLSX를 만들어줘.
원본은 보존하고 처리 기준·행 수·합계와 결과 수식을 확인해줘.
실행 방법이나 코드만이 아니라 실제로 받을 수 있는 결과 파일과 분석 요약을 전달해줘.
외부 서비스에 공유하지 말고, 불가능한 단계만 구체적으로 알려줘.
```

**문서 작성 또는 연결된 문서 수정**

```text
WebGPT pro로 첨부 메모를 바탕으로 검토용 DOCX 보고서를 완성해줘.
출처와 불확실성을 구분하고, 내용과 페이지 배치를 확인해 필요한 부분을 교정해줘.
개요만 주지 말고 완성된 파일을 전달해줘. 다른 사람에게 보내거나 공개하지 마.
```

연결된 문서를 직접 수정하는 요청이라면 정확한 문서와 수정 범위를 지정합니다. 워커는 해당
앱에서 원본을 읽고 승인된 수정을 수행한 뒤 가능한 재조회로 확인합니다. 수정 방법을 부모에게
설명하는 것으로 대체하거나 로컬 사본·Git 등록을 필수 단계로 만들지 않습니다. 검토만 또는
초안만 요청했다면 그 결과가 완료이며, 원본 수정·발송·공유로 범위를 넓히지 않습니다.

**저장소 리뷰 — 프로젝트 전체 읽기 권한**

```text
WebGPT xh로 C:\projects\my-app 저장소의 로그인 흐름을 리뷰해줘.
프로젝트 루트 전체에 read 권한을 부여해서 관련 구현과 테스트를 직접 읽게 해줘.
재현 가능한 결함을 우선하고 파일 위치, 영향, 수정 방향과 검증하지 못한 점을 알려줘.
파일은 수정하지 말고 웹 워커가 가능한 근거 확인까지 마친 뒤 미검증 부분을 구분해줘.
```

**기능 구현 — 프로젝트 전체 수정 권한**

```text
WebGPT pro로 C:\projects\my-app에 검색 결과 필터를 구현해줘.
프로젝트 루트 전체에 edit 권한을 부여하고 기존 구조와 동작을 확인한 뒤 직접 수정하게 해줘.
기존 사용자 변경을 보존하고 관련 테스트도 필요한 범위에서 수정해줘.
WebGPT가 실제로 가능한 검사와 실패 교정까지 마친 뒤 변경과 검사 근거를 전달해줘.
Codex는 결과를 검토하고, 부모 환경에서만 가능한 검사가 남으면 그 부분만 수행해줘.
```

실제 코드 작업에는 선택한 채팅에서 정확한 프로젝트의 파일 도구를 사용할 수 있는지
확인합니다. 관련 파일을 찾을 수 있도록 루트 전체를 `read` 또는 `edit`로 부여하고,
파일별 허용 목록으로 대체하지 않습니다. 직접 접근이 없으면 연결 문제를 보고합니다.
사용자가 패치만 요청하지 않았다면 텍스트 답변이나 패치를 Codex가 대신 적용하는 것으로
직접 구현을 대체하지 않습니다. 프로젝트 내부의 불필요한 비밀정보는 전달하지 않으며,
분리가 필요하면 정리된 프로젝트 사본을 사용합니다. 비공개 런타임 자료는 프로젝트 밖에 둡니다.

코드 수정에는 [개발 절차](development-loop.md)를 활용합니다. 작은 수정은 전체 파일 SHA를
유지한 `write_file.oldText`의 정확한 구간 치환, 이어 읽기는 `read_file.expectedSha256`의
리비전 고정을 사용할 수 있습니다. 실제 설치 스키마가 해당 인자를 제공하는지 확인하며,
구버전에서 `oldText`만 빼서 호출하지 않습니다. 그러면 교체할 구간이 전체 파일을 덮어씁니다.
부모 전용 검사가 필요한 경우에만 관련 검사를 묶어 실행하고 실제 리비전·종료 코드·실패 근거를 전달합니다.
Node 테스트에는 선택적 실패 요약 리포터를 사용하되 빈 보고서를 PASS로 해석하지 않습니다.

**대형·바이너리 파일 및 CLI 결과 — 실제 접근 경로로 구분**

프로젝트 파일 도구의 직접 편집은 여전히 UTF-8·파일당 1 MiB 이내입니다. 워커가 첨부나
별도 승인 도구로 원본에 접근해 처리할 수 있으면 해당 도구의 실제 한도에서 직접 수행합니다.
부모 호스트에만 있는 자료의 근거 준비에는 [부모 전용 도구](artifact-inputs.md)를 사용할 수 있습니다.
승인된 256 MiB 이하 파일 하나의 전체 해시와 명시적으로 선택한 텍스트/hex 구간을
작은 입력으로 준비합니다. 기본값은 내용 없는 메타데이터이며, 구간은 합계 8 KiB 이내입니다.
부모가 민감정보와 관련성을 확인한 **근거 파일의 본문**을 named `inputs`로 전달하고 워커는
`read_input`으로 읽습니다. 부모 로컬 경로나 stdout 영수증만 보내는 것이 아닙니다.
이 도구는 MCP의 실행·바이너리 쓰기 권한을 추가하지 않습니다. 필수 이미지·PDF 첨부를
요약/hex로 임의 대체하거나 이미 접근 가능한 입력을 다시 내보내지 않습니다. 결과 파일의 생성,
검증, 요청 위치 저장을 구분하고, 워커가 못 하는 실제 전송만 남았다면 부모가 내용을 다시
만들지 않고 승인된 경로로 옮기도록 합니다. sandbox 경로만으로 로컬 저장 완료를 주장하지 않습니다.

**조사 — 프로젝트 권한 없음**

```text
WebGPT xh로 이 주제의 공개 자료를 조사해줘: [주제와 핵심 질문].
기준 날짜, 출처 링크, 확인된 사실과 추정, 자료 간 불일치를 구분해줘.
로컬 프로젝트 접근은 필요 없어. 웹 워커가 핵심 출처와 결론을 대조한 완성된 보고서를 전달해줘.
```

조사는 `workspace` 없이 등록하거나 연결 없는 텍스트 작업으로 진행할 수 있습니다.
이 선택은 로컬 코드 작업의 접근 권한을 생략하는 우회 방법이 아닙니다.

## 후속 수정과 병렬 작업

관련 후속 작업은 보존된 같은 채팅에서 이어갑니다. 예를 들어 “방금 결과의 오류 처리도
검토해줘” 또는 “Codex 테스트에서 확인한 아래 실패를 같은 채팅에서 수정해줘”라고 요청합니다.
이전 등록이 실행 중이라면 먼저 현재 상태와 산출물을 확인합니다. `submit_result`로 이미
종료된 작업은 파일 접근이 닫히므로, 추가 읽기·수정에는 같은 채팅에 새 작업 ID와 새 토큰을
등록합니다. 먼저 이전 결과의 수용 판단·수집과 최종 채팅 답변 완료를 확인합니다.
종료된 ID나 회수된 토큰을 재사용하지 않습니다. 채팅 재사용은 전송 기록을
초기화하거나 불확실한 프롬프트를 다시 보내는 근거가 아닙니다.

독립된 일이면 다음처럼 분리할 수 있습니다.

```text
WebGPT로 두 작업을 병렬 진행해줘. 같은 프로젝트에 필요한 권한을 부여하되
A는 docs/의 사용자 문서, B는 tests/의 회귀 테스트를 담당하게 해줘.
각자 다른 작업자의 변경을 보존하고 공통 파일 수정이 필요하면 먼저 Codex에 알려줘.
Codex가 결과를 모아 일관성과 테스트를 확인해줘.
```

작업별 채팅·등록·비공개 전송 기록을 유지하고 수정 소유권을 겹치지 않게 나눕니다.
한 작업이 다른 작업의 변경에 의존하면 순서대로 진행합니다. 동시 실행 제한이나 throttling이
관찰되면 동시성을 줄이고, 동일 작업을 새 채팅으로 반복 생성하지 않습니다.

## 결과 확인과 보존

부모는 일반 Node로 등록·전송 기록·작업별 대기·수집을 처리하고, CUA는 허용된 브라우저 조작에만
사용합니다. [dispatch.md](dispatch.md)의 실제 새 메시지 확인과 [필수 첨부 확인](file-uploads.md)을
지킵니다. 작업자의 완성된 산출물과 검사 근거를 받아 핵심 주장·입력/결과 버전·전달 상태를
확인합니다. 충분한 근거를 재사용하며 부족한 검증만 추가하고, 수용/부분수용/거부 및 미검증
항목을 기록합니다. 해시 일치는 내용의 정답이나 테스트 수행 증거가 아닙니다.

소유한 단일 작업은 [결과 검토](result-review.md)의 `client.mjs review <작업-ID>`를 사용합니다.
무결성을 확인한 `review.content`를 먼저 읽되 수집하지는 않습니다. `review: null`이면 성공으로
간주하지 말고 복구·중단·백업 확인 알림 등을 처리합니다. 여러 작업이나 메타데이터만 기다릴 때는
`wait <작업-ID> ...`를 사용합니다. 관련 변경·검사·수용 판단을 마친 뒤 `collect <작업-ID>`로
수집하며, 이미 읽은 본문이나 정상 수집이 수행한 확인을 매번 다시 조회하지 않습니다.
중단/오류에는 기존 기록으로 명시적 재개를 합니다. `collect --resume`은 미수집 결과를 수집할 수
있으므로 무조건 읽기 전용은 아닙니다. 검증/무결성 오류를 unchecked ack·결과 삭제·자동 재전송으로
우회하지 않습니다.

최종 보고에서는 WebGPT가 실제로 기여한 부분과 부모가 검증·통합한 부분을 구분합니다. 실행하지
못한 검사는 `NOT_RUN`으로 남깁니다. 채팅은 기본 보존하고 종료된 작업의 토큰/백업 확인과 소유
탭을 정리합니다. 결과 제출·수집과 최종 채팅 답변의 완료는 별개이므로, 답변 완료를 확인한 뒤
해당 작업의 탭만 닫습니다. 삭제는 명시적으로 요청된 채팅만 대상으로 합니다. [정확한 정리 절차](chat-lifecycle.md)를 따릅니다.

## 로컬 controller 연결 오류

오류 상태·권한·복구 조건과 호환성은 [collection-details.md](collection-details.md)에 보존했습니다.
일반 사용에는 부모 흐름을 먼저 읽고, 수집 구현/장애를 검토할 때 상세 계약을 확인합니다.
